# Default keybinds of the X11 window managers: sources and how to change them

Data: `data/keybinds/<id>.json`, regenerated by `scripts/keybinds/extract-x11-wms.py [id ...]`
(nix + python3; builds `github:NixOS/nixpkgs/nixos-26.05#<pkg>` and `#<pkg>.src`, reads the
shipped default config or the source). All 22 files pass `check-keybinds.py` (problems: 0).

Conventions used in every file:
- Binds with the same `action` are merged into one entry with several `accels` (like GNOME's
  `as` keys), so `action` is unique within a file.
- Mouse binds are left out. Modal maps (menus, move/resize mode, query line editing) are left out.
- Prefix WMs (ratpoison, StumpWM, Notion submaps, pekwm chains): accel = the first combo of the
  sequence, the whole sequence is in the label.
- Modifier mapping: Mod1/Alt/Meta/`M`/`A` -> `<Alt>`, Mod4/Super/`W`/`s` -> `<Super>`. Hyper binds
  are skipped (only sawfish has one: `H-ISO_Left_Tab`). "Any modifier" (fvwm `A`, AfterStep `A`,
  e16 `*`) is written as no modifier, with "(with any modifiers)" in the label.
- Single letters are lower case; where upper case means Shift (xmonad) Shift is added.

NixOS facts used below (nixos-26.05):
- `XDG_CONFIG_DIRS` starts with `/etc/xdg` (nixos/modules/programs/environment.nix: "needs to be
  before profile-relative paths to allow changes through environment.etc"), then
  `/run/current-system/sw/etc/xdg` etc. So `environment.etc."xdg/<wm>/<file>"` shadows the
  package's `etc/xdg` copy for WMs that search `XDG_CONFIG_DIRS`, as long as the user has no file
  in `~/.config`.
- The `services.xserver.windowManager.<wm>` modules mostly start `${pkgs.<wm>}/bin/<wm>` with no
  arguments and have no config option. Where a WM takes a config-file flag, the no-rebuild route is
  an overlay that wraps the binary:
  ```nix
  nixpkgs.overlays = [ (final: prev: {
    cwm = prev.symlinkJoin {
      name = "cwm-configured"; paths = [ prev.cwm ];
      nativeBuildInputs = [ prev.makeWrapper ];
      postBuild = "wrapProgram $out/bin/cwm --add-flags '-c /etc/cwmrc'";
    };
  }) ];
  ```
  (cwm's module runs plain `cwm` from PATH; the others use `${pkgs.X}/bin/X`, which the overlay
  also replaces.) A flag-given file replaces the user's own file for that WM.
- Where the default config is read from the package's own store path (sysconfdir/datadir compiled
  in), a system-wide change needs a package override that rebuilds it (`overrideAttrs` with a
  `postInstall` that replaces the file), or the flag wrapper above.

## openbox — 24 binds (24 accels)
Source: `<keyboard>` of `etc/xdg/openbox/rc.xml` (openbox 3.6.1). Action = the keybind's
`<action>` element(s) serialized on one line, e.g. `<action name="Close" />`.
Change: openbox reads the first `openbox/rc.xml` in `$XDG_CONFIG_HOME`, then `$XDG_CONFIG_DIRS`, so
`environment.etc."xdg/openbox/rc.xml".text = …` works system-wide (users without
`~/.config/openbox/rc.xml`). It must be the **whole** rc.xml: take the package file and rewrite the
`<keyboard>` section. A second `<keybind key="A-F4">` does **not** override: openbox appends its
actions to the existing binding (keyboard.c: "already bound to something, use the existing tree";
`t->actions = g_slist_append(...)`), so change = edit the element, remove = delete it.
Syntax: `<keybind key="W-e"><action name="Execute"><command>foot</command></action></keybind>`;
modifiers `S` Shift, `C` Control, `A` Alt, `W` Super, `M` Meta, `H` Hyper, joined with `-`.
Also `openbox --config-file FILE`.
**Easy: file override (full rc.xml, /etc/xdg).**

## icewm — 85 binds (89 accels)
Source: the `Key*` preferences (defaults listed as comments in `share/icewm/preferences`, IceWM
3.8.2; action = preference name, e.g. `KeyWinClose`) plus the launcher lines of `share/icewm/keys`
(action = the command; `switchkey icewm-menu-xrandr` for the switchkey line).
Lookup: each file is taken from the first of `$ICEWM_PRIVCFG` (default `~/.icewm`), `/etc/icewm`
(compiled in), `share/icewm`. So:
- Preferences: `environment.etc."icewm/preferences".text` with only the changed lines, e.g.
  `KeyWinClose="Super+q"`; remove with `KeyWinClose=""`. Unset keys keep the compiled default.
  Stronger: `/etc/icewm/prefoverride` (same syntax) is read after `preferences` and overrides even a
  user's preferences (unless they have their own prefoverride).
- Launchers: `environment.etc."icewm/keys".text` is the **whole** keys file (it shadows
  share/icewm/keys). Syntax: `key "Alt+Ctrl+t" xterm`, `switchkey "Super+p" icewm-menu-xrandr`.
  Modifiers `Alt Ctrl Shift Super Meta Hyper AltGr`, joined with `+`. `Esc`/`Del` in the defaults
  are IceWM aliases (written as `Escape`/`Delete` in the data; IceWM accepts both).
**Easy: /etc/icewm files (preferences per key; keys file whole).**

## fluxbox — 67 binds (67 accels)
Source: `share/fluxbox/keys` (fluxbox 1.3.7). Action = the command after the colon
(`NextWindow {groups} (workspace=[current])`, `Workspace 1`, `Exec xterm`). The three volume keys
are raw keycodes 176/174/160 upstream; the data gives them as `XF86AudioRaiseVolume`,
`XF86AudioLowerVolume`, `XF86AudioMute` (label says "(keycode N)").
Change: on first start fluxbox creates `~/.fluxbox` and copies init/keys/menu/… from the compiled-in
defaults (`FluxboxCli::setupConfigFiles`), then only reads `session.keyFile` (default
`~/.fluxbox/keys`). There is no system file read at runtime. Options:
1. Package override replacing `$out/share/fluxbox/keys` (rebuild): affects users whose
   `~/.fluxbox` doesn't exist yet — i.e. the users the installer creates. Simplest.
2. Wrapper `fluxbox -rc /etc/fluxbox/init` with `session.keyFile: /etc/fluxbox/keys` in that init
   (fluxbox also writes to its init; a read-only one may warn).
Keys file syntax: `Mod4 Return :Exec foot`. How duplicate lines for one key resolve wasn't
checked — write the whole file; remove = drop the line.
**Needs a full keys file; per-user copy on first start (package override or -rc wrapper).**

## awesome — 74 binds (74 accels)
Source: "Key bindings" section of `etc/xdg/awesome/rc.lua` (awesome 4.3), modkey = Mod4.
Action = `globalkeys: <function>` or `clientkeys: <function>` as written (whitespace collapsed;
the `for i = 1, 9` tag loop spelled out with i filled in; its keys are keycodes `#10`–`#18`, shown as
1–9). Labels/groups from each key's `description`/`group`.
Change: awesome searches `awesome/rc.lua` in `$XDG_CONFIG_HOME` then `$XDG_CONFIG_DIRS`
(awesome.c `xdgSearchableConfigDirectories`, `luaA_find_config`), then its compiled default, and
falls back to the next one if an rc.lua fails. So `environment.etc."xdg/awesome/rc.lua".text` works.
It is Lua, so it must be a whole rc.lua: copy the package's rc.lua and replace the `awful.key(...)`
calls (change modifiers/key, drop the call to remove, add `awful.key({ modkey }, "b",
function () awful.spawn("firefox") end, {description = "…", group = "launcher"})` to globalkeys).
A thinner alternative (dofile the stock rc.lua, then filter `root.keys()`) works for globalkeys
only; clientkeys are captured by `awful.rules` — not recommended.
**Full config (Lua) in /etc/xdg; file override works.**

## bspwm — 85 binds (85 accels)
Source: `share/doc/bspwm/examples/sxhkdrc` (bspwm 0.9.12). bspwm binds no keys itself; sxhkd does.
Action = the shell command, braces expanded (`bspc node -f west`); `@space` (on release) is shown
as a press.
Important: the NixOS module runs `sxhkd` with `-c <configFile>` only when
`services.xserver.windowManager.bspwm.sxhkd.configFile` is set; default null means
`~/.config/sxhkd/sxhkdrc`, which a fresh user doesn't have — **no keybinds at all** (and without
`…bspwm.configFile`, no bspwmrc: no desktops). So the generator should always set both:
```nix
services.xserver.windowManager.bspwm.configFile = "${pkgs.bspwm}/share/doc/bspwm/examples/bspwmrc";
services.xserver.windowManager.bspwm.sxhkd.configFile = pkgs.writeText "sxhkdrc" ''
  super + Return
  	foot
  …
'';
```
sxhkdrc syntax: hotkey line (`super + shift + w`, modifiers `super hyper meta alt control ctrl
shift mode_switch lock mod1…mod5`), then the command indented on the next line. Write the whole
file (expanded, one hotkey per entry, or re-braced); remove = leave out. Note the example uses
`urxvt` and `dmenu_run`, which aren't installed by default. `-c` replaces the user's file.
**Easy: NixOS option (full sxhkdrc).**

## xmonad — 45 binds (48 accels)
Source: `keys` in `src/XMonad/Config.hs` (xmonad 0.18.1), `defaultModMask = mod1Mask` (Alt).
Action = the Haskell `X ()` expression (`windows W.focusDown`, `windows $ W.greedyView "1"`,
`screenWorkspace 0 >>= flip whenJust (windows . W.view)`); labels are its `%!` comments.
**Compiled in**: changing them takes an xmonad.hs. NixOS builds it from
`services.xserver.windowManager.xmonad.config` (string or path; binary built with
writeHaskellBin, no runtime ghc unless `enableConfiguredRecompile`):
```haskell
import XMonad
import qualified Data.Map as M
main = xmonad def { keys = \c -> myKeys c `M.union` foldr M.delete (keys def c) removed }
  where
    removed = [ (mod1Mask .|. shiftMask, xK_p) ]
    myKeys c = M.fromList [ ((mod1Mask, xK_b), spawn "firefox") ]
```
(`M.union` is left-biased, so myKeys also rebinds.) With
`enableContribAndExtras = true`, `XMonad.Util.EZConfig`'s `additionalKeysP`/`removeKeysP` read
nicer (`"M-S-p"`). Note the docs on `config`: the stock `mod-q` restart calls `xmonad --recompile`,
which doesn't fit a Nix-built config; bind it to `restart "xmonad" True`.
**Compiled in: needs a generated xmonad.hs (option `…xmonad.config`).**

## herbstluftwm — 53 binds (65 accels)
Source: `etc/xdg/herbstluftwm/autostart` (0.9.5), `Mod=Mod1` (Alt). Action = the herbstclient
command after `hc keybind KEY` (variables filled in, e.g. `resize left +0.02`; the tag loop spelled
out: `use_index 0` … `move_index 8`).
Lookup: `$XDG_CONFIG_HOME/herbstluftwm/autostart` (or `-c PATH`), else the compiled-in global
path (the package's etc/xdg). The NixOS option
`services.xserver.windowManager.herbstluftwm.configFile` passes `-c` (replaces the user's file).
Because keybinds are runtime commands, the generator can keep the stock autostart and patch on top:
```nix
services.xserver.windowManager.herbstluftwm.configFile = pkgs.writeShellScript "autostart" ''
  ${pkgs.herbstluftwm}/etc/xdg/herbstluftwm/autostart
  herbstclient keyunbind Mod1-Shift-q
  herbstclient keybind Mod1-Return spawn foot
'';
```
`keybind` on an already-bound combo replaces it (keymanager.cpp: `removeKeyBinding(newBinding.keyCombo)`
before adding); `keyunbind COMBO` removes; `keyunbind --all` clears. Combo syntax
`Mod1-Shift-q` (`-` or `+`), modifiers `Mod1…Mod5 Alt Super Shift Control Ctrl`.
**Easy: NixOS option; incremental keybind/keyunbind after the stock autostart.**

## fvwm3 — 15 binds (16 accels)
Source: the `Key`/`Silent Key` lines of `share/fvwm3/default-config/config` (fvwm3 1.1.0).
Action = `<context> <command>` (e.g. `A Menu MenuFvwmRoot`, `WTSF ShuffleDir up`); context is
needed to rebind.
Lookup: `~/.fvwm/config` (`$FVWM_USERDIR`), then files in the compiled `FVWM_DATADIR`, finally
`default-config/config`. No /etc. Use the wrapper route: `fvwm3 -f /etc/fvwm3/config` with
```
Read /nix/store/…-fvwm3/share/fvwm3/default-config/config
Key F1 A M -                       # remove (action "-")
Key Return A 4 Exec exec foot      # add / replace (same key+context+mods replaces)
```
(`-f` replaces the user's ~/.fvwm/config.) Syntax `Key <keysym> <context> <mods> <action>`,
mods `N` none, `A` any, `C S M 1-5` (`4` = Super). Or package override of
`share/fvwm3/default-config/config`.
**Wrapper flag (-f) + incremental Key lines, or package override.**

## jwm — 10 binds (18 accels)
Source: `<Key>` elements with a `mask` in `etc/system.jwmrc` (JWM 2.4.6). Unmasked ones
(up/down/left/right/select/escape, h/j/k/l, Return, Escape) only navigate menus and are left out.
Action = the element text (`close`, `root:1`, `desktop#`); `key="#"` = number keys 1–9 (binding.c
expands `#` to 1..9), so `desktop#` is one entry with 9 accels.
Lookup: `~/.jwmrc`, else the compiled path `$out/etc/system.jwmrc`. `jwm -f FILE` exists. So
wrapper `jwm -f /etc/jwm/system.jwmrc`, where the file can be
```xml
<JWM>
  <Include>/nix/store/…-jwm-2.4.6/etc/system.jwmrc</Include>
  <Key mask="4" key="Return">exec:foot</Key>
</JWM>
```
A later `<Key>` with the same mask+key replaces the earlier (binding.c `RemoveDuplicates`). There is
no "unbind" action; to remove, write the full file without it (or bind to `exec:true`). Mask letters
`A`/`1` Alt, `C` Control, `S` Shift, `4` Super, `2 3 5`.
**Wrapper flag (-f), full or included file.**

## windowmaker — 22 binds (22 accels)
Source: the `*Key` settings of `etc/WindowMaker/WindowMaker` (global defaults domain, 0.96.0),
`None` skipped. Action = the setting name (`RootMenuKey`, `Workspace1Key`, `ScreenCaptureKey`).
Lookup: user domain `~/GNUstep/Defaults/WindowMaker` over the global domain in the compiled
`$out/etc/WindowMaker` — per key (user keys override, others come from the global file). No /etc.
System-wide: package override (rebuild) editing `$out/etc/WindowMaker/WindowMaker`, e.g.
`CloseKey = "Mod4+Q";`, remove with `RootMenuKey = None;`. Syntax: `Mod1+Control+Right`
(modifiers `Mod1…Mod5 Control Shift`; the global `ModifierKey = Mod1`). Per user: the installer could
seed `~/GNUstep/Defaults/WindowMaker` with just the changed keys (user config).
**Package override (property-list file, per-key).**

## spectrwm — 124 binds (126 accels)
Source: `setup_keybindings()` in `spectrwm.c` (3.7.0; the shipped `etc/spectrwm.conf` has them only
commented), `MODKEY = Mod1` (Alt). Action = spectrwm's action name as `bind[...]` takes it
(`ws_1`, `mvws_12`, `rg_3`, `focus_next`), or the program name for spawn binds (`term`, `menu`,
`lock`, `screenshot_all`, `screenshot_wind`, `initscr`). Labels from spectrwm(1).
Lookup (spectrwm.c 18494ff.): `~/.spectrwm.conf`, `$XDG_CONFIG_HOME/spectrwm/spectrwm.conf`,
`$XDG_CONFIG_DIRS/spectrwm/spectrwm.conf`, `/etc/spectrwm.conf` — the first found. The conf is
applied on top of the compiled defaults. So:
```nix
environment.etc."xdg/spectrwm/spectrwm.conf".text = ''
  bind[]            = MOD+p            # unbind
  bind[term]        = MOD+Return       # rebind an action
  program[browser]  = firefox
  bind[browser]     = MOD+Shift+b
'';
```
(`/etc/spectrwm.conf` works too.) `modkey = Mod4` changes MOD for all binds. Don't use
`keyboard_mapping` (it clears all binds). Modifiers `MOD Mod1…Mod5 Shift Control`.
**Easy: /etc/xdg file, incremental.**

## leftwm — 35 binds (43 accels)
Source: `Config::default()` in `leftwm/src/config/default.rs` (0.5.4), modkey = Mod4.
Action = `<command> <value>` as config.ron has them (`Execute dmenu_run`, `GotoTag 3`,
`CloseWindow`); two values are computed at runtime and shown as `Execute default_terminal()`
(first of alacritty, termite, kitty, urxvt, rxvt, st, roxterm, eterm, xterm on PATH) and
`Execute exit_strategy()` (`loginctl kill-session $XDG_SESSION_ID`, else `pkill leftwm`).
Lookup: only `$XDG_CONFIG_HOME/leftwm/config.ron` (xdg `place_config_file`; also writes the default
there on first start). No system path, no flag, NixOS module has no option.
Change: write the user's `~/.config/leftwm/config.ron` at install (whole `keybind: [...]` list,
entries `(command: Execute, value: "foot", modifier: ["modkey", "Shift"], key: "Return")`;
remove = leave out), or patch default.rs (Rust rebuild).
**Needs a full config in the user's home (or a patched build).**

## pekwm — 202 binds (202 accels)
Source: the `Global` section of `etc/pekwm/keys` (0.3.2), including its Chains. MoveResize,
InputDialog and Menu sections are modal, left out. Action = the `Actions` string
(`GotoWorkspace 1`, `Exec $TERM`); a chain bind is written as its Chain block,
`Chain = "Ctrl Mod4 C" { KeyPress = "Q" { Actions = "MoveToEdge TopLeft" } }`, accel = the
chain's first combo, label `Ctrl+Mod4+C, Q: …`.
Lookup (Config.cc `tryHardLoadConfig`): `$PEKWM_CONFIG_FILE` or `~/.pekwm/config`; if missing, pekwm
copies autoproperties/config/keys/menu/mouse/start/vars from the compiled `$out/etc/pekwm` into that
directory; last resort the store config. `Files { Keys = "$_PEKWM_CONFIG_PATH/keys" }` (config_system)
is relative to the config's directory. System-wide:
`environment.sessionVariables.PEKWM_CONFIG_FILE = "/etc/pekwm/config";` plus **all** of those files
in `/etc/pekwm` (copy the package's, replace `keys`), since pekwm would otherwise try to copy into
the read-only dir. Or package override of `$out/etc/pekwm/keys` (new users only, copied on first
start). Keys syntax: `KeyPress = "Mod4 Return" { Actions = "Exec foot" }` inside `Global { }`;
modifiers `Mod1 Mod4 Ctrl Shift`. Write the whole file.
**Needs a full keys file (env var + /etc/pekwm, or package override).**

## ratpoison — 53 binds (53 accels)
Source: `initialize_default_keybindings()` in `src/actions.c` (1.4.9), prefix `C-t`
(`conf.h`), `TERM_PROG` = xterm (configure.ac default; nixpkgs passes no `--with-xterm`). Every
bind but `readkey root` (the prefix itself) is `C-t <key>` in the root keymap: accel `<Control>t`,
label with the sequences (`C-t c, C-t C-c: Open a terminal (xterm)`). Action = the ratpoison
command (`exec xterm`, `next`, `select 3`); same command merged.
Lookup: `~/.ratpoisonrc`, else `$sysconfdir/ratpoisonrc` = the store path (`$out/etc`, nothing
there). The rc adds to the compiled defaults. Options: package override with
`configureFlags = old ++ [ "--sysconfdir=/etc" ]` (rebuild) + `environment.etc."ratpoisonrc"`, or
wrapper `ratpoison -f /etc/ratpoisonrc` (replaces ~/.ratpoisonrc). Syntax:
```
bind c exec foot          # C-t c
unbind k                  # remove C-t k
escape C-z                # change the prefix
definekey top s-Return exec foot   # a direct (prefix-less) bind
```
**rc file on top of compiled defaults; needs sysconfdir override or -f wrapper.**

## stumpwm — 122 binds (122 accels)
Source: the `fill-keymap` forms of `bindings.lisp` (24.11) for tile groups (the default group type):
`*root-map*`, `*group-root-map*`, `*tile-group-root-map*`, `*groups-map*` (C-t g), 
`*exchange-window-map*` (C-t x), `*help-map*` (C-t h), plus `?`/`C-h` help in every map.
Float-group maps (`*float-group-root-map*`: n, p) left out. Action = `<keymap> <command>`
(`*root-map* exec xterm`), accel `<Control>t`, sequences in the label.
Lookup (stumpwm.lisp `load-rc-file`): `~/.stumpwmrc`, `~/.stumpwm.d/init.lisp`,
`$XDG_CONFIG_HOME/stumpwm/config`, `/etc/stumpwmrc` — the first found. So
`environment.etc."stumpwmrc".text` works for users without their own rc, on top of the defaults:
```lisp
(in-package :stumpwm)
(define-key *root-map* (kbd "c") "exec foot")      ; rebind C-t c
(undefine-key *root-map* (kbd "e"))                ; remove C-t e
(define-key *top-map* (kbd "s-Return") "exec foot") ; direct bind, no prefix
(set-prefix-key (kbd "C-z"))
```
Note a key bound in several active maps: *tile-group-root-map* is searched before *root-map*
(e.g. `o`, `n` are in group maps). Keys: `C-` Control, `M-` Meta, `s-` Super, `S-` Shift, `H-`.
**Easy: /etc/stumpwmrc (Lisp, incremental).**

## notion — 70 binds (74 accels)
Source: the `defbindings` of `etc/notion/cfg_bindings.lua` (loaded via cfg_defaults →
cfg_notioncore), `cfg_tiling.lua`, `cfg_dock.lua`, `cfg_sp.lua` (4.0.4); `META = "Mod4+"`,
`ALTMETA = "Mod4+Shift+"` (ioncore_ext.lua defaults). Modal maps (WMoveresMode, WEdln, WInput,
WMenu) left out. Action = `<context>: <lua>` (`WScreen: WScreen.switch_nth(_, 0)`); the one submap
bind is `WScreen: submap Mod4+O: …`, accel `<Super>o`. Some keys are bound in several contexts
(e.g. Mod4+D: dock toggle in WScreen, tab 2 in WFrame.toplevel; Mod4+H/V in WFrame and
WFrame.toplevel) — kept as separate entries.
Lookup: `~/.notion/<file>` first, then the compiled `$out/etc/notion`. `-searchdir` dirs are added
**after** the built-in ones, so they can't shadow. System-wide: package override (rebuild) that
appends `dopath("cfg_configurator")` to `etc/notion/cfg_notion.lua` and installs:
```lua
defbindings("WScreen", {
    kpress("Mod4+1", nil),                                   -- remove (nil action = unbind)
    kpress("Mod4+Return", "ioncore.exec_on(_, 'foot')"),     -- add / replace
})
```
(conf-bindings.c: a nil func removes the binding.) The context must match the original one.
**Package override + incremental Lua.**

## dwm — 60 binds (60 accels)
Source: `keys[]` in `config.def.h` (dwm 6.6), `MODKEY = Mod1Mask` (Alt), TAGKEYS expanded.
Action = `<function> <argument>` as keys[] writes them (`spawn {.v = termcmd }`,
`view {.ui = 1 << 2}`).
**Compiled in.** nixpkgs' dwm takes a whole config header:
```nix
services.xserver.windowManager.dwm.package = pkgs.dwm.override { conf = ./config.def.h; };
```
(`conf` is a path or a string; it's copied over config.def.h, then dwm is rebuilt — seconds.) The
renderer should take the upstream config.def.h (same source the script reads) and rewrite the
`keys[]` entries: `{ MODKEY|ShiftMask, XK_Return, spawn, {.v = termcmd } },`; new programs need a
`static const char *xcmd[] = { "foot", NULL };`. Remove = drop the line (for TAGKEYS, expand the
macro first). Masks `Mod1Mask Mod4Mask ShiftMask ControlMask`.
**Compiled in: needs a generated config.h (dwm.package override).**
