# Default keybinds: Pantheon, Budgie, Cinnamon, MATE

Generated by `scripts/keybinds/extract-dconf-desktops.py` (nixos-26.05):

    nix shell nixpkgs/nixos-26.05#glib.bin nixpkgs/nixos-26.05#python3 \
      -c scripts/keybinds/extract-dconf-desktops.py [pantheon budgie cinnamon mate]

Method: effective defaults exactly as the session sees them. Each NixOS module
sets `NIX_GSETTINGS_OVERRIDES_DIR` to a `*-gsettings-overrides` package
(compiled schemas + vendor `.gschema.override` files); nixpkgs' glib prepends
it to the schema search path. The script sets `GSETTINGS_SCHEMA_DIR` to that
dir followed by the packages' own schema dirs and `XDG_CURRENT_DESKTOP` to the
session's value (overrides use per-desktop sections like `[...:Pantheon]`,
`[...:Budgie]`), then `gsettings list-recursively`. Labels are `<summary>`
from the XMLs. Empty strings, `''` entries and Marco's `'disabled'` are
dropped; keys with no binding left are omitted. All four pass
check-keybinds.py with problems: 0.

Applying a change: system dconf defaults (`programs.dconf.profiles.user.databases
= [{ settings = { "<path>" = { <key> = ...; }; }; }]`) take precedence over
schema defaults and overrides for every one of these schemas (all are plain,
non-relocatable schemas with fixed paths), and the user can still change them.
An unbind writes an empty value: `[]` (as) / `''` (s; for Marco `'disabled'`
is the canonical "none", `''` works too).

## Pantheon (Gala 8.5.1)

- Overrides package: `pantheon.elementary-gsettings-schemas` (gala, elementary-dock,
  gnome-settings-daemon, gsettings-desktop-schemas, gtk3, mutter, evolution-data-server
  XMLs + gala's and elementary-default-settings' overrides). `XDG_CURRENT_DESKTOP=Pantheon`.
- Schemas (dconf paths):
  - `io.elementary.desktop.wm.keybindings` `/io/elementary/desktop/wm/keybindings/`: Gala's
    own (multitasking view, screenshots, zoom, PiP, workspace first/last, input source).
  - `io.elementary.dock.keybindings` `/io/elementary/dock/keybindings/`: `<Super>1..9`.
  - `org.gnome.desktop.wm.keybindings`, `org.gnome.mutter.keybindings`,
    `org.gnome.mutter.wayland.keybindings` (`/org/gnome/desktop/wm/keybindings/`, ...):
    Gala is a libmutter compositor, so mutter's built-in handlers read these.
    elementary overrides many (`maximize=[]`, `toggle-maximized=<Ctrl><Super>Up`,
    workspaces on `<Super><Shift>N` / `<Super><Alt>N`, ...).
  - `org.gnome.settings-daemon.plugins.media-keys`: Pantheon runs
    `pantheon.gnome-settings-daemon` (media-keys plugin). Includes the `-static` keys, as
    gnome.json does (gsd listens on both `<key>` and `<key>-static`).
  - `org.gnome.mutter overlay-key` = `'Super_L'` (type s, modifier-only): Gala opens the
    Applications Menu on it.
- Duplicates (upstream as-is): `<Super><Shift>End` on both
  `org.gnome.desktop.wm.keybindings/move-to-workspace-last` and Gala's
  `move-to-workspace-last`; `<Super>End` likewise for switch-to-workspace-last;
  `<Alt><Super>8` on gsd `magnifier` and wm `move-to-workspace-8`.
- Custom commands: gsd's `custom-keybindings` under
  `/org/gnome/settings-daemon/plugins/media-keys/` (same as GNOME).

## Budgie (10.10.2, on labwc)

- Budgie 10.10 dropped magpie/mutter: the session is **labwc**, and budgie's
  `libexec/budgie-desktop/labwc_bridge.py` (autostart `org.buddiesofbudgie.labwc-bridge`)
  copies `share/budgie-desktop/labwc/rc.xml` to `~/.config/budgie-desktop/labwc/rc.xml`
  and rewrites each `<keybind bridge="<last two schema components>/<key>">` from
  GSettings at startup and on change (then `labwc -r`). So **only bridged keys work**;
  the file lists only those (89 bridge entries in rc.xml, 70 with a default; e.g.
  `raise`, `lower`, `toggle-fullscreen`, `switch-windows`, workspaces 2-4 have none).
  Not bridged, so omitted though they have defaults (they do nothing under labwc):
  budgie-wm `show-power-dialog`, `take-window-screenshot`; wm `activate-window-menu`,
  `move-to-workspace-up/down`, `switch-to-workspace-up/down`; mutter `cancel-input-capture`,
  `rotate-monitor`, `switch-monitor`; media keys for battery, hibernate, suspend, power,
  keyboard brightness, playback forward/random/repeat/rewind, rfkill, rotation lock,
  brightness cycle, touchpad on/off/toggle, and the quiet/precise volume variants.
- Schemas read by the bridge: `org.gnome.desktop.wm.keybindings`,
  `org.gnome.mutter.keybindings`, `org.gnome.mutter` (`overlay-key`),
  `com.solus-project.budgie-wm` (`/com/solus-project/budgie-wm/`: Raven, notifications,
  screenshots), `org.buddiesofbudgie.settings-daemon.plugins.media-keys`
  (`/org/buddiesofbudgie/settings-daemon/plugins/media-keys/`), **not** GNOME's gsd schema.
- Overrides package: `budgie-gsettings-overrides`; `XDG_CURRENT_DESKTOP=Budgie:GNOME`
  (its `[org.gnome.desktop.wm.keybindings:Budgie]` sets show-desktop `<Super>d` and the
  input-source keys).
- `-static`: when a media key's main value is empty the bridge uses `<key>-static`.
  Most of budgie's media keys are `['']` with the real key in `-static`, so for those the
  file lists the **`-static` key as the action** (rebinding or unbinding it is what takes
  effect while the main key stays empty; writing `[]` to the main key alone would not
  unbind). Where the main key has a value (`help`, `logout`, `terminal`, `screensaver`,
  magnifier zoom, ...) the main key is listed.
- `overlay-key` = `'Super_L'` (s, modifier-only, `onRelease`): opens the Budgie menu.
  `switch-input-source` includes `<Alt>Shift_L` (modifier-only key).
- The bridge's converter (`calc_keybind`) knows only `<Alt> <Super> <Control> <Primary>
  <Ctrl> <Shift>`; write binds with those (no `<Mod4>`/`<Hyper>`). Uppercase letters in
  defaults (`<Super>C`) are lowercased by it.
- Custom commands: relocatable `org.buddiesofbudgie.settings-daemon.plugins.media-keys.custom-keybinding`
  at paths listed in that schema's `custom-keybindings`; the bridge keys them by the
  path's last component (matches the existing `budgie-dconf` renderer).

## Cinnamon (6.6)

- Overrides package: `cinnamon-gsettings-overrides` (+ cinnamon, cinnamon-desktop, muffin,
  cinnamon-settings-daemon). `XDG_CURRENT_DESKTOP=X-Cinnamon`.
- Schemas: `org.cinnamon.desktop.keybindings` (`/org/cinnamon/desktop/keybindings/`:
  Looking Glass, desklets, magnifier), `org.cinnamon.desktop.keybindings.wm`
  (`.../keybindings/wm/`, read by Muffin), `org.cinnamon.desktop.keybindings.media-keys`
  (`.../keybindings/media-keys/`, handled by Cinnamon itself since media keys moved out of
  csd), `org.cinnamon.muffin.wayland.keybindings` (`/org/cinnamon/muffin/wayland/keybindings/`,
  VT switching; only matters in a Wayland session). `org.cinnamon.muffin.keybindings` has no
  defaults. Media keys have no `-static` twins.
- The menu's Super key is **not** GSettings: `org.cinnamon.muffin overlay-key` is `''`;
  the menu applet's own JSON (`~/.config/cinnamon/spices/menu@cinnamon.org/*.json`,
  `overlay-key` `Super_L::Super_R`) binds it. Not in the file.
- `switch-group` uses `Above_Tab` (a mutter/muffin pseudo-keysym for the key above Tab).
- Workspace N keys (1-12) have no defaults.
- Custom commands: `custom-list` (as, names) in `/org/cinnamon/desktop/keybindings/` plus
  `/org/cinnamon/desktop/keybindings/custom-keybindings/<name>/` with `name` (s),
  `command` (s), `binding` (**as**).

## MATE (1.28, Marco)

- Packages: `mate-gsettings-overrides` (only gsettings-desktop-schemas + mate-wayland-session,
  nothing keybinding-related), `marco`, `mate-settings-daemon`. `XDG_CURRENT_DESKTOP=MATE`.
- Schemas: `org.mate.Marco.global-keybindings` (`/org/mate/marco/global-keybindings/`),
  `org.mate.Marco.window-keybindings` (`/org/mate/marco/window-keybindings/`),
  `org.mate.SettingsDaemon.plugins.media-keys` (`/org/mate/settings-daemon/plugins/media-keys/`).
- **Every key is type `s` (one accel), not an array**; `'disabled'` = unbound (dropped).
  Modifiers include `<Mod4>` in some upstream strings (none in the current defaults).
- `run-command-screenshot` / `run-command-window-screenshot` run the commands in
  `org.mate.Marco.keybinding-commands` (`command-screenshot`, ...); custom commands use
  `run-command-N` + `command-N` (12 slots), as the existing `mate-dconf` renderer does.
- The optional MATE Wayland session (wayfire) doesn't read Marco's keys.
