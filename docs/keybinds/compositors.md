# Default keybinds: sway, i3, Hyprland, niri, labwc, river, Wayfire, MangoWC

Researched 2026-09-26 against nixpkgs `nixos-26.05` (the packages and their
`.src`). Every claim below was read in the source or the shipped docs; paths
are store paths of that pin. Nothing here was tested in a VM.

Data: `data/keybinds/<id>.json`, regenerated by
`python3 scripts/keybinds/extract-compositors.py [id ...]` (needs `nix`; it
builds/substitutes the packages, libxkbcommon for keysym names and lua5_4 for
Hyprland). `check-keybinds.py` on all eight: problems: 0.

| id | package (version) | source of the defaults | actions | combos |
|---|---|---|---|---|
| sway | `sway` 1.12 | `etc/sway/config` | 56 | 65 |
| i3 | `i3` 4.24 | `etc/i3/config` | 50 | 58 |
| hyprland | `hyprland` 0.55.4 | `share/hypr/hyprland.lua` | 43 | 44 |
| niri | `niri` 26.04 | `niri.src` `resources/default-config.kdl` | 88 | 111 |
| labwc | `labwc` 0.9.7 | `labwc.src` `include/config/default-bindings.h` | 15 | 15 |
| river | `river-classic` 0.3.17 | `example/init` | 82 | 83 |
| wayfire | `wayfire` 0.10.1 | `share/wayfire/metadata/*.xml` (default plugins) | 31 | 36 |
| mangowc | `mangowc` 0.12.8 | `etc/mango/config.conf` | 66 | 66 |

Common to all files: accels are GTK accelerators with modifiers in the order
Super, Control, Alt, Shift and keys as canonical XKB names (letters lower
case; `Page_Up`/`Page_Down` rather than XKB's `Prior`/`Next`). Left out
everywhere: mouse buttons, scroll/wheel/touchpad, gestures, switches, binds
inside modes/submaps (the bind entering a mode is kept).

**Renderer pitfall shared by several:** the action + accel pair is not enough
to *remove* a default in every desktop: sway needs the bind's flags
(`--locked`), Hyprland its original key string, niri its original modifier
spelling (`Mod` vs `Super`). The per-desktop rules below say how to recover
them.

## sway

- **Source:** `/nix/store/…-sway-unwrapped-1.12/etc/sway/config` (the wrapped
  `sway` links it). NixOS: `programs.sway` sets
  `environment.etc."sway/config".source = mkOptionDefault "${cfg.package}/etc/sway/config"`
  and adds `/etc/sway/config.d/nixos.conf`
  (`nixos/modules/programs/wayland/sway.nix:158-170`).
- **Data:** `$mod`=Mod4, `$term`=foot, `$menu`=wmenu-run resolved. The 11
  XF86 binds (audio, player, brightness) are **`bindsym --locked`**; `Print`
  and all others have no flags. Resize mode's binds left out; `mode "resize"`
  kept.
- **System-wide file:** the default config ends with
  `include /etc/sway/config.d/*` (`sway.src` `config.in:241`, sysconfdir
  `/etc`). A user who copied the default to `~/.config/sway/config` keeps
  that include line; a user config without it ignores `/etc`.
- **Later bind on the same keys:** overwrites the earlier one, but only when
  the *flags match* (`--locked`, `--release`, `--border`, … are part of the
  identity: `sway/commands/bind.c:64-80` `binding_key_compare`). Overwriting
  shows a **swaynag warning** ("Overwriting binding …",
  `bind.c:285-296`) unless the new bind has `--no-warn`
  (`sway.5.scd:431-441`).
- **Remove:** `unbindsym [flags] <combo>`, with the **same flags** as the
  bind (`sway.5.scd:908-913`). Unbinding something not bound with those
  flags is `CMD_FAILURE` "Could not find binding `…` for the given flags"
  (`bind.c:319`) → a config error bar. So: `unbindsym --locked XF86AudioMute`
  (a plain `unbindsym XF86AudioMute` fails). Rule for the renderer: every
  default whose accel is an `XF86*` key needs `--locked`, nothing else does.
  A plain `bindsym XF86AudioMute …` next to the locked default is not an
  overwrite: both exist, the unlocked one wins while unlocked
  (`sway/input/keyboard.c:158-250`), the locked default still fires on the
  lock screen.
- **Syntax:** `bindsym Mod4+Shift+q kill`; modifiers `Mod4`/`Super`,
  `Control`/`Ctrl`, `Mod1`/`Alt`, `Shift`. Rebinding an action to new keys:
  `unbindsym Mod4+Shift+q` then `bindsym Mod4+x kill` (or `bindsym --no-warn`
  to overwrite in place).

## i3

- **Source:** `/nix/store/…-i3-4.24/etc/i3/config` (Mod1 = **Alt**; the
  keysym config). i3 also ships `etc/i3/config.keycodes`, the template
  `i3-config-wizard` turns into `~/.config/i3/config` asking Win or Alt; the
  default config runs `exec i3-config-wizard`, so on first login a user may
  end up with a Super-based copy that then overrides everything.
- **Data:** `$ws1…$ws10` resolved as written (`workspace number "1"`),
  `$refresh_i3status` resolved, `$up/$down/$left/$right` = l/k/j/semicolon.
  Resize mode left out, `mode "resize"` kept.
- **Config lookup** (binary strings): `$XDG_CONFIG_HOME/i3/config`,
  `~/.i3/config`, `$XDG_CONFIG_DIRS/i3/config`, then the store's
  `etc/i3/config`. NixOS puts `/etc/xdg` first in `XDG_CONFIG_DIRS`
  (`nixos/modules/programs/environment.nix:34`). Two routes:
  - `environment.etc."xdg/i3/config"`: used when the user has no config
    (preferred; the user can still override).
  - `services.xserver.windowManager.i3.configFile`: writes `/etc/i3/config`
    and starts `i3 -c /etc/i3/config` (`…/window-managers/i3.nix:77,84`),
    which **ignores any user config**.
- **Later bind on the same keys:** a duplicate is a config **error**
  ("Duplicate keybinding in config file", i3-nagbar;
  `i3.src` `src/bindings.c:784-808`) and the **first** one wins at runtime
  (`get_binding` returns the first match, `bindings.c:229`).
- **Remove:** i3 has **no unbind** command. `include` (4.20+) only adds
  ("included files can only add to the configuration, not undo",
  `docs/userguide:423`). So the renderer must write a **whole config**: the
  default text with the lines of removed/rebound combos dropped (and
  `exec i3-config-wizard` dropped), plus the new `bindsym` lines.
- **Syntax:** `bindsym Mod1+Shift+q kill`, `bindsym Mod4+Return exec foot`
  (`Mod4`=Super, `Mod1`=Alt, `Control`, `Shift`).

## Hyprland (0.55, Lua)

- **Source:** `/nix/store/…-hyprland-0.55.4/share/hypr/hyprland.lua` =
  upstream `example/hyprland.lua`. When no config exists Hyprland writes it
  to `~/.config/hypr/hyprland.lua` with an `hl.config({ autogenerated = true })`
  header (warning overlay) (`src/config/lua/DefaultConfig.hpp`,
  `ConfigManager.cpp:792-825`). Extracted by running the file in Lua 5.4
  with a stub `hl`, so the loop-generated workspace binds are expanded.
- **Data:** the action is the dispatcher as a Lua expression, variables
  resolved: `hl.dsp.exec_cmd("kitty")`, `hl.dsp.window.close()`,
  `hl.dsp.focus({ workspace = 3 })`, `hl.dsp.window.float({ action = "toggle" })`
  (table keys sorted; all default tables have one key). Bind options are not
  in the action: all XF86 binds pass `{ locked = true }`, volume/mute/mic and
  brightness also `repeating = true`. Mouse (`mouse:272/273`) and scroll
  (`mouse_down/up`) binds left out.
- **Config lookup** (`src/config/supplementary/jeremy/Jeremy.cpp:19-50`,
  hyprutils `src/path/Path.cpp:59-93`): `--config`, `$HYPRLAND_CONFIG`,
  then `hyprland.lua` in `$XDG_CONFIG_HOME/hypr`, `~/.config/hypr`, each
  `$XDG_CONFIG_DIRS/hypr`, `/etc/xdg/hypr`; only if no `.lua` exists anywhere,
  the same search for `hyprland.conf`. **System-wide file:
  `environment.etc."xdg/hypr/hyprland.lua"`** (NixOS has `/etc/xdg` in
  `XDG_CONFIG_DIRS`). Caveats: a user `~/.config/hypr/hyprland.lua` wins; but
  a user's legacy **`hyprland.conf` (e.g. Home Manager's hyprlang) loses to
  `/etc/xdg/hypr/hyprland.lua`**, since every `.lua` location is searched
  before any `.conf`. With the `/etc/xdg` file present no autogenerated
  config is written.
- The Lua state has the full stdlib (`luaL_openlibs`,
  `ConfigManager.cpp:313`) and `package.path` = the config's directory, so
  `/etc/xdg/hypr/hyprland.lua` can `dofile("${pkgs.hyprland}/share/hypr/hyprland.lua")`
  and then change binds (or `require("configurator-keybinds")` from
  `/etc/xdg/hypr/`).
- **Later bind on the same keys:** does **not** replace: `hl.bind` appends
  (`KeybindManager.cpp:184-192`) and a key press runs **every** matching bind
  (`handleKeybinds` collects every match into `bindsHit` and dispatches them all, `KeybindManager.cpp:601-760`). So unbind
  first.
- **Remove:** `hl.unbind("SUPER + Q")` (`LuaBindingsToplevel.cpp:353-365`)
  removes binds whose `displayKey` (the **exact string passed to `hl.bind`**,
  `LuaBindingsToplevel.cpp:150`) equals the argument after removing spaces
  and lower-casing (`KeybindManager.cpp:201-216`). Modifier **order
  matters**: the defaults are written `SUPER + <key>`, `SUPER + SHIFT + <key>`
  and bare `XF86…`; keys as written: `Q C M E V R P J S`, `left right up
  down`, digits `1…9 0`. So render Super first, then Shift, key upper-case
  letters or the lower-case arrow names, e.g. `hl.unbind("SUPER + SHIFT + 1")`,
  `hl.unbind("SUPER + left")`, `hl.unbind("XF86AudioMute")`.
  (`hl.unbind("all")` clears every bind.) The handle returned by `hl.bind`
  has `:remove()`/`:set_enabled(false)`, not reachable for binds made inside
  a `dofile`d file.
- **Syntax:** `hl.bind("SUPER + SHIFT + X", hl.dsp.exec_cmd("foot"))`;
  modifiers `SUPER`, `CTRL`/`CONTROL`, `ALT`, `SHIFT`
  (`stringToModMask`, `KeybindManager.cpp:218-235`); options as a third
  table (`{ locked = true, repeating = true }`) — keep them when moving a
  media action.

## niri (26.04)

- **Source:** `niri.src` `resources/default-config.kdl` (embedded in the
  binary; written to `~/.config/niri/config.kdl` when neither the user nor
  the system config exists).
- **Data:** the action is the KDL action node inside the braces:
  `spawn "alacritty"`, `spawn-sh "wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle"`,
  `focus-column-left`, `focus-workspace 3`, `set-column-width "-10%"`,
  `quit`. Bind properties are not part of it: `repeat=false` (Mod+O, Mod+Q),
  `allow-when-locked=true` (all XF86 and Super+Alt+S),
  `hotkey-overlay-title=…` (Mod+T, Mod+D, Super+Alt+L; `=null` on
  Super+Alt+S), `cooldown-ms` (wheel only), `allow-inhibiting=false`
  (Mod+Escape). Wheel/touchpad binds left out.
- **Config lookup** (`src/main.rs:327-362`, `niri-config/src/lib.rs:98-114`,
  `:552-570`): `--config`/`$NIRI_CONFIG`, else
  `$XDG_CONFIG_HOME/niri/config.kdl`, else **`/etc/niri/config.kdl`**, else
  create the user file from the default. NixOS's `programs.niri` writes no
  `/etc` file. `include "<path>"` is supported.
- **Later bind on the same keys:** a later `binds {}` section (e.g. after an
  `include`) **replaces** earlier binds with an equal key
  (`niri-config/src/lib.rs:219-230`); the same key twice inside one `binds`
  block is an **error** (`binds.rs:763-800`).
- **Key equality trap:** `Mod` is its own modifier bit (`COMPOSITOR`), not
  `SUPER` (`binds.rs:57-67`, parsing `binds.rs:946-970`). So `Super+T` does
  **not** replace the default `Mod+T`; both stay, and at runtime the first
  match in list order wins (`find_configured_bind`,
  `src/input/mod.rs:4443-4475`), which is the default (the override is
  appended). **To replace a default, write its keys the way the default
  config does:** every Super bind is `Mod+…` except **`Super+Alt+L`** and
  **`Super+Alt+S`**. (The current `crates/flakegen/src/keybinds.rs` niri
  renderer writes `Super+…`, so its binds on a default's keys don't
  override it.) Other names: `Ctrl`, `Alt`, `Shift`; keys match XKB names
  case-insensitively (`binds.rs:1004-1027`).
- **Remove:** no unbind. Options: (a) bind the keys to a no-op
  (`Mod+Q { spawn "true"; }`) in the override section; (b) don't `include`
  the default: write `/etc/niri/config.kdl` as the default config text with
  the removed/rebound bind lines filtered out (every default bind is one
  line), plus the new binds.
- **Syntax:** `binds { Mod+Shift+X hotkey-overlay-title="Open foot" { spawn "foot"; } }`;
  media keys want `allow-when-locked=true`.

## labwc (0.9.7)

- **Source:** `labwc.src` `include/config/default-bindings.h`
  (`key_combos[]`), the same list as `docs/rc.xml.all` and
  `labwc-config(5)` `<keyboard><default />`. Loaded when rc.xml has no
  `<keybind>` at all (`src/config/rcxml.c:1690-1694`) or has
  `<keyboard><default />` (`rcxml.c:1068-1070`).
- **Data:** the action is the rc.xml element:
  `<action name="SnapToEdge" direction="left" combine="yes" />`,
  `<action name="Execute" command="lab-sensible-terminal" />`. Key names in
  labwc's own list are `W-a`, `A-Space`, `XF86_AudioMute` (xkbcommon accepts
  the `XF86_` spelling); accels use XKB names.
- **Config lookup** (`labwc-config.5.scd:16-30`):
  `${XDG_CONFIG_HOME:-~/.config}/labwc/rc.xml`, then
  `${XDG_CONFIG_DIRS:-/etc/xdg}/labwc/rc.xml`; the **first file found is the
  only one read** (unless labwc runs with `--merge-config`). **System-wide:
  `environment.etc."xdg/labwc/rc.xml"`**; NixOS's `programs.labwc` writes
  nothing there. A user rc.xml replaces it entirely.
- **Later bind on the same keys:** replaces the earlier one (same modifiers
  and keysyms; `deduplicate_key_bindings`, `rcxml.c:1629-1660`,
  `keybind.c:37-49`), so `<default />` first, then own binds.
- **Remove:** a keybind whose only action is `<action name="None" />`
  clears an earlier one on the same keys (`labwc-actions.5.scd:435-437`,
  `rcxml.c:1744-1747`).
- **Syntax:** `<?xml version="1.0"?><labwc_config><keyboard><default /><keybind key="W-Return"><action name="Execute" command="foot" /></keybind><keybind key="A-F4"><action name="None" /></keybind></keyboard></labwc_config>`;
  modifiers `W` (super), `C`, `A`, `S` (`labwc-config.5.scd:763-771`).

## river (river-classic 0.3.17)

- **Source:** `/nix/store/…-river-classic-0.3.17/example/init`, executed with
  a stub `riverctl` (loops expanded). **river has no built-in binds and no
  system config:** it runs `$XDG_CONFIG_HOME/river/init` or
  `~/.config/river/init`, nothing else (`river/main.zig:174-198`); without
  it the session has no keybinds. The example is what users copy there.
- **Data:** `riverctl map normal …` binds; the action is the riverctl command
  after the key, shell-quoted (`send-layout-cmd rivertile 'main-ratio -0.05'`,
  `set-focused-tags 4`, `spawn 'pamixer -i 5'`); tag masks resolved
  (Super+0 = `4294967295`). The media binds are also mapped in the `locked`
  mode; pointer maps and the `passthrough` mode's exit bind left out;
  `enter-mode passthrough` kept.
- **System-wide:** no `/etc` path. The renderer has to provide an init and
  make river run it when the user has none, e.g. an executable
  `/etc/river/init` plus a session wrapper
  `river -c 'init="${XDG_CONFIG_HOME:-$HOME/.config}/river/init"; if [ -x "$init" ]; then exec "$init"; else exec /etc/river/init; fi'`
  (`-c` runs `sh -c <command>` instead of the default init,
  `main.zig:42`) installed as its own session (`.desktop`) or via
  `programs.river-classic.package`. The init itself can be
  `. ${pkgs.river-classic}/example/init` followed by our riverctl lines.
- **Later bind on the same keys:** `map` on the same mode + modifiers + key
  (+ `-release`) **replaces** it (`river/command/map.zig:86-100`; it prints
  "overwrote an existing keybinding" on riverctl's stdout, harmless).
- **Remove:** `riverctl unmap normal Super Q` (`riverctl.1.scd:242-249`);
  media keys also `riverctl unmap locked None XF86AudioMute`.
- **Syntax:** `riverctl map normal Super+Shift Return spawn foot`; modifiers
  `Super`, `Alt`, `Control`, `Shift`, `None` joined with `+`
  (`riverctl.1.scd:195-240`).

## Wayfire (0.10.1)

- **Source:** the runtime defaults, not the example `wayfire.ini` in the
  source (which isn't installed and differs: it adds `[command]` launchers
  and uses Ctrl+Super for vswitch). Wayfire's defaults are the `<default>`
  of each `key`/`activator` option in `share/wayfire/metadata/<plugin>.xml`
  for the plugins in `core/plugins`' default (`core.xml`: alpha animate
  autostart command cube decoration expo fast-switcher fisheye
  foreign-toplevel grid gtk-shell idle invert move oswitch place resize
  session-lock shortcuts-inhibit switcher vswitch wayfire-shell window-rules
  wobbly wrot zoom). No command (launcher) binds exist by default.
- **Data:** the action is `section/option` as wayfire.ini names it
  (`grid/slot_l`, `core/close_top_view`). One option can hold several combos
  (`<super> KEY_Q | <alt> KEY_F4`): all are in accels. Keys are evdev codes
  (`KEY_LEFT`, `KEY_KP4`, layout-independent), mapped to keysyms by US
  position. `wayfire-shell/toggle_menu` is the Super key alone (accel
  `Super`, as GNOME's overlay-key). Left out: button options (move, resize,
  wrot drag, cube `<ctrl> <alt> BTN_LEFT`), scroll modifiers (zoom, alpha).
- **Config layers** (`src/default-config-backend.cpp:60-118`, wf-config
  `src/file.cpp:603-645`): XML defaults → **`/etc/wayfire/defaults.ini`**
  (nixpkgs builds with `--sysconfdir /etc`; its values *become the
  defaults*) → the user file (`--config`, `$WAYFIRE_CONFIG_FILE`,
  `~/.config/wayfire/wayfire.ini`, else `~/.config/wayfire.ini`). The user
  file only overrides the options it sets, so `/etc/wayfire/defaults.ini`
  stays in effect alongside a user config. NixOS's `programs.wayfire`
  writes nothing to `/etc/wayfire`.
- **Catch:** `defaults.ini` only applies to options that exist in the XML
  (`override_defaults`: otherwise "Unused default value", `file.cpp:627-630`).
  `[command] binding_foo`/`command_foo` belong to a dynamic list, not a
  registered option, so **new command/launch binds can't be added from
  `/etc/wayfire/defaults.ini`**; only in the user's wayfire.ini (Home
  Manager `wayland.windowManager.wayfire.settings`) or a whole config
  selected by `$WAYFIRE_CONFIG_FILE`/`--config` (which replaces the user's).
- **Same keys on two options:** all matching bindings fire
  (`src/core/seat/bindings-repository.cpp:49-80`), so clear the default
  first.
- **Remove / rebind:** set the option: `[grid]` `slot_l = none` (or
  `disabled`, wf-config `src/types.cpp:337-338`); to drop one of several
  combos, write the remaining ones joined by ` | `; to move an action,
  `slot_l = <super> <shift> KEY_H`.
- **Syntax:** modifiers `<super> <ctrl> <alt> <shift>`, keys `KEY_*` from
  `linux/input-event-codes.h`, alternatives with `|`.

## MangoWC (0.12.8)

- **Source:** `/nix/store/…-mangowc-0.12.8/etc/mango/config.conf`, upstream's
  `assets/config.conf`. mango reads `~/.config/mango/config.conf`, else
  **`/etc/mango/config.conf`** (`src/config/parse_config.h:3525-3550`,
  `SYSCONFDIR` = `/etc`, `meson.build:75`). **NixOS's `programs.mangowc`
  doesn't put the file in `/etc`**,
  so a stock NixOS mango session without a user config has only its
  hard-coded Ctrl+Alt+F1…F12 VT switches (`parse_config.h:129-131`,
  appended after every config, not removable) and logs "Failed to open
  config file".
- **Data:** the action is `function,arguments` as the bind line writes it
  after the key (`spawn,foot`, `view,1,0`, `killclient` with its trailing
  comma dropped). No keymodes in the default. Mouse (`mousebind`), axis and
  gesture binds and the VT switches left out.
- **System-wide:** `environment.etc."mango/config.conf"`; `source=<path>` /
  `source-optional=<path>` include other files (`parse_config.h:2702-2705`).
- **Later bind on the same keys:** does **not** replace: every matching bind
  runs in file order (`src/mango.c:3739-3780`; a bind only stops the loop if
  its function returns "break").
- **Remove:** no unbind. The renderer writes `/etc/mango/config.conf` as the
  shipped default text with the lines of removed/rebound combos filtered
  out, plus the new binds (not `source=` the default).
- **Syntax:** `bind=SUPER+SHIFT,Return,spawn,foot` (modifiers `SUPER`,
  `CTRL`, `ALT`, `SHIFT`, `NONE`, case-insensitive; flags `bindl` =
  also when locked, `binds` = keysym instead of keycode, `docs/bindings/keys.md`).
